# 工程06 — 全作品への展開と不要要素の整理

## 状態

実装とローカルブラウザーでの基本確認を実施。作品ごとの担当範囲・公開素材・外部リンクの到達性は未確認事項が残るため、工程06全体は未完了。

## 実施内容

### トップページ

- 導入を制作者名、ポートフォリオの対象、作品への導線に整理。
- Kaomoji Clash初版とBomb Crashを代表作品として表示。チーム制作作品には「担当確認中」を明記。
- 作品の技術例から対応する詳細ページの説明箇所へ直接移動できるようにした。
- Algomate Colony、FingerDojo、Reloaded、補足作品を別カテゴリに分け、初期表示では非代表カテゴリを隠す。各カテゴリ切替の表示件数を確認。
- サムネイルを実ゲーム画面と断定しない代替テキストに修正。

### 作品ページ

- **Algomate Colony:** チーム制作と本人担当確認中を明記。確認できない制作期間・環境等を削除し、Waypointsと局所的なRaycast回避を経路探索アルゴリズムと混同しない表現に整理。外部ソース・資料リンクを調査時コミットに固定。
- **Bomb Crash:** チーム制作と担当未確認を明記。未確認の実行ファイル導線や期間・環境情報を除去。コード構成の説明と本人の実装実績を区別し、ソースリンクを調査時コミットに固定。
- **FingerDojo:** 試作状態、チーム制作、本人担当・共同制作者表記の確認中を明記。目次から削除済みセクションへのリンクを除去し、未実装コマンドの注記を重複させないよう整理。重複して使われていた画像を削除し、ソース・資料リンクを調査時コミットに固定。
- **Kaomoji Clash:** 未確認の期間情報を除去し、本人確認済みの個人制作・企画・プログラミングという表記を維持。
- **Kaomoji Clash / Reloaded:** README記載の制作途中状態と調査時コードから確認できる処理を中心に整理。初版との違いは設計意図や実動作比較として扱わず、調査時点の静的なコード上の差として記載。動画をコードや仕様の証拠と結び付けず、ソースリンクを調査時コミットに固定。
- 詳細ページの仮`#`リンクをトップまたは該当作品へ接続し、見出しの非機能リンクを削除。
- Kaomoji Clash / Reloaded の比較表に、モバイルで縦積みになる既存デザイントークン準拠のスタイルを追加。
- 作品ページの viewport 設定から拡大操作を無効化する指定を除去。

## 削除・統合した情報

- 本人確認や一次資料で裏付けられていない制作期間、Unityバージョン、対応プラットフォーム、配布ビルドへの導線。
- チーム制作作品で、本人の担当範囲を確認せず実装者と受け取られる表現。
- ページ内に存在しないセクションへの目次リンクと遷移しない仮リンク。
- FingerDojoで内容が一致しない重複画像と、試作状態を繰り返す説明。
- Reloadedで、意図・成果・実行を証明できない「改善」「設計上の工夫」といった評価表現。

## 表示・技術確認

- ローカルHTMLファイルを統合ブラウザーで表示。
- トップの初期表示は代表作品2件。技術ケース・小作品フィルターでは2件（Algomate Colony、FingerDojo）、補足作品・開発中フィルターでは3件、代表作品に戻すと2件であることを確認。
- トップ、Algomate Colony、Bomb Crash、FingerDojo、Kaomoji Clash、Reloadedをデスクトップ幅と390×844相当のモバイル幅で確認。いずれも検査時点で水平オーバーフローなし。
- 全6ページでローカル画像の読み込みエラー、壊れたページ内フラグメント、仮`href="#"`リンクは0件。
- Reloadedの比較表は4行を表示し、モバイル幅で水平オーバーフローしないことを確認。
- トップのカテゴリーフィルターを操作し、代表2件、技術2件、補足3件の表示と代表カテゴリへの復帰を確認。
- 最終差分に対する `git diff --check` は成功。GitからCRLF→LFの作業ツリー警告は出たが、空白エラーはなし。

## 未確認・残課題

- GitHub上の外部ソース・資料リンクの到達性、公開後の相対パスとGitHub Pagesの構成。
- YouTube/Google Drive動画の再生、各動画の現行ページ・対象コードとの一致、全素材の利用許可。
- Bomb Crashなどチーム制作における本人の具体的な担当範囲と共同制作者の表記。
- Algomate Colony等の現在の制作状態・配布物の有無。本人が説明できる技術内容と設計意図。
- Unity Editor上の動作、ビルド、自動テスト、性能計測。ポートフォリオHTML表示の確認は作品本体の検証を意味しない。
- PC/モバイルの視覚的な詳細レビュー、キーボード操作、拡大縮小時のアクセシビリティ。
- 技術サンプル・補足作品の掲載継続判断と、各動画・外部公開先の現状。

## 次に行うこと

2. 外部リンク、動画、公開URLを別途確認する。未検証の結果を成功として報告しない。
3. PC/モバイルの視覚的な詳細レビューとキーボード・拡大表示のアクセシビリティ検証を行う。
4. 確認結果を踏まえて全作品横断レビューを完了し、工程06の完了可否を判断する。
