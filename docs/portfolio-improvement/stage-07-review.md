# 工程07 — 実装品質・アクセシビリティ・表示速度の確認

## 状態

主要なローカル品質チェック、画面幅確認、代表的な公開URLの到達確認と、検出した読みやすさ・フォーカス表示の問題を修正した。外部リンク全件、動画の再生、拡大表示、性能計測、Unity作品本体の実行は未確認のため、工程07は未完了。

## 確認環境と方法

- 統合ブラウザーでローカルの静的ページを確認。トップページとAlgomate Colonyのデスクトップ／モバイル表示を目視した。
- HTML 7ページをブラウザーDOMで検査。画面幅は320、375、390、768、1024、1440 CSS pxで `document.documentElement.scrollWidth > window.innerWidth` を確認した。
- 公開URLと代表的な外部サービスは `curl.exe` のRangeリクエスト（`-r 0-0`）で応答を確認した。`206 Partial Content` は部分応答として記録し、動画の再生や外部ページの内容確認とは区別する。

## 修正内容

- 作品詳細のh1と見出し階層を、既存の外観を保つCSSで支援。リンク画像に適切なaltを付け、トップ／作品ページの画面外画像をlazy loadに設定した（作品カード以外の上部画像は初期表示用として維持）。
- 作品説明、概要カード、技術解説、図注、処理フロー、コードブロックの文字を読みやすい大きさへ調整。トップの作品ラベル・概要文も拡大した。装飾目的の小さな英字見出しは対象外。
- Algomate Colonyの資料リンクを14px以上かつ44px高の操作領域に調整。
- Tab操作時に一部の技術例リンクがブラウザー既定の輪郭色のままになっていたため、全リンクとボタンの `:focus-visible` に明瞭な輪郭を設定。サイドバー導入文はJavaScriptによるDOM移動後も対象になるセレクターに変更。
- サイドバーの重複した説明文を「Unity / C#の制作作品と実装例を紹介しています。」へ更新。
- `prefers-reduced-motion` 環境ではフィルター切替後のスクロールをsmoothにしない。
- 淡いホバー文字色を濃色に変更し、ジャンルラベルと操作対象を読みやすくした。

## 表示速度・保守性

- トップのヒーロー画像は初期表示用としてeager、作品カード・下部画像・動画iframeはlazy loading。画像の非同期デコード属性も利用している。
- 大きな素材の例はBomb Crashサムネイル約1.67 MB、Sword Slicerサムネイル約1.35 MB、Hiyokoアイコン約1.05 MB。画質・表示幅を比較できる最適化ツールが確認できなかったため、画像変換や上書きはしていない。
- Lighthouse、Core Web Vitals、通信量、実機レンダリング時間は計測していない。数値性能の改善は主張しない。
- HTML/CSS/JavaScript中心の静的構成と既存の依存関係を維持。新たな依存は追加していない。

## 検証上の注意と未確認事項

- ブラウザーコンソールに埋め込み動画由来の警告・通信中断が記録された。YouTube APIへのリクエスト中断はページ移動と同時に観測されたものを含み、動画本体の再生成否とは判定していない。
- 公開ページのRange応答は公開パスの到達を示すが、キャッシュ反映状況、全アセットの公開、全ページの実機表示を保証しない。
- 外部リンク全件の応答、Google Driveの閲覧権限、リンク先資料の現行性は未確認。
- YouTube/Drive動画の実再生、コード解説と動画映像の一致、本人の掲載許可は未確認。
- 200%拡大、スクリーンリーダー、実機タッチ、実機ブラウザーでの表示・操作は未確認。
- 画像最適化、Lighthouse等の性能測定、Unity作品本体の実行・ビルド・テストは未実施。
- GitHub上のPages設定やデプロイワークフローは未調査。公開URLの到達確認を設定の調査完了とは扱わない。
- `git diff --check` は既存CSSのCRLF行末を追加行上の末尾空白として検出する。`git -c core.whitespace=cr-at-eol diff --check` では通過。実際に追加したセレクター行に空白文字はない。既存のCRLFは変換していない。
